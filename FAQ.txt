================================================================================
                      D2RLOADER  -  FREQUENTLY ASKED QUESTIONS
================================================================================


--------------------------------------------------------------------------------
  GETTING STARTED
--------------------------------------------------------------------------------


Q: Where do I install the launcher?
A: Anywhere. It's fully portable. It only writes to its own folder
   (launcher_config.json, plugin_manifest.json, assets\seeds.json,
   assets\playtime.json), to the per-mod "Launcher Files\" subfolders, and
   to D2RLoader.toml in your D2R install.


Q: The launcher can't find D2R. What do I do?
A: At startup the launcher tells you if it couldn't detect your install. Use
   the "..." button in the LOADER OPTIONS section header (bottom-left) and
   pick your "Diablo II Resurrected" folder (the one containing D2R.exe).
   The path persists in launcher_config.json.


Q: What if my D2R install is on a different drive or an unusual path?
A: Same answer - use the "..." button and point it at the folder. Any folder
   containing D2R.exe / D2RLoader.exe works.


Q: Where did the "Options" nav button go?
A: v1.4 removed the Options nav button. Settings live in the Basic Options
   and Developer Options modals in the LOADER OPTIONS section now. If you
   want to hand-edit keys the launcher doesn't surface, open D2RLoader.toml
   directly with your editor of choice - the launcher only touches specific
   keys and leaves the rest of the file alone.


Q: It says "No Mods Found" at startup.
A: The launcher looked in <D2R>\mods\ and found nothing. Use "Nexus Mod
   Directory" (center column) to find mods, put the mod folder in
   <D2R>\mods\, then click Refresh. (You can browse your mod folders with
   the left-rail "Mods" button - see the MODS TOOL section below.)


--------------------------------------------------------------------------------
  THE MOD LIST
--------------------------------------------------------------------------------


Q: My mod isn't appearing in the list.
A: Check three things:
   1. The mod folder is directly inside <D2R>\mods\, not nested deeper
   2. There's a modinfo.json file
   3. The launcher knows where D2R is (use the "..." button in the
      LOADER OPTIONS section header if you haven't picked it yet)
   The launcher watches the mods folder, so when something changes the
   "Refresh" button highlights - click it to rescan.


Q: I added a mod but the list didn't update.
A: The launcher doesn't auto-rescan (that would flicker the UI). When it
   notices a change, the Refresh button highlights. Click Refresh to pick up
   the new state. You can also click Refresh any time.


Q: A mod shows up but with the wrong name.
A: The launcher uses modinfo.json fields in this priority order:
       1. "title" (if present)
       2. "name"
       3. The folder name itself
   Add a "title" field to modinfo.json for a nicer display name.


Q: How many mods does the list show at once?
A: Up to 5 rows are visible at any time. If you have more than 5 mods, use
   the scrollbar on the right edge of the list (or the mouse wheel) to scroll
   to the rest. The number of installed mods is unlimited.


Q: How do I get a mod's banner to show?
A: The mod author needs to:
   1. Add a "Launcher Files\" subfolder inside the mod's folder
   2. Drop a banner image in there
   3. Add "banner": "filename.jpg" to modinfo.json
   The banner fills the mod's row as a background. See README.txt > BANNERS.


Q: My banner looks cropped.
A: Rows use "cover" semantics - the image scales to fill the row and crops the
   overflow. The row is much wider than it is tall, so tall or square images
   get cropped top and bottom. Use a wide image, or bake your layout (name /
   author / version) directly into the banner art.


Q: My mod has no banner. What shows instead?
A: A clean text fallback: the row is transparent (the panel's stone background
   shows through) with the mod name on top and "by Author    v X.Y.Z" on a
   second line (the version sits at the row's horizontal midpoint). There's
   no hard dark box around it, just text on stone.


Q: Why are the Discord/Docs/Website buttons missing for my mod?
A: They only appear if the matching field exists in modinfo.json. Add any of:
       "docs":    "./docs/manual.pdf"
       "website": "https://example.com"
       "discord": "https://discord.gg/abc123"
   These can be URLs or file paths (relative or absolute).


Q: Why don't the Discord/Docs/Website buttons grow on hover like the others?
A: They're deliberately flat - they have a click-shrink animation (to confirm
   the press) but no hover-grow, so they match the title-bar minimize/close
   buttons and the Refresh button. The Nexus and Update Selected Mod buttons
   still grow on hover because they're meant to read as more prominent calls
   to action.


Q: What does the small tooltip that appears when I hover a mod row show?
A: Per-mod playtime tracking. After hovering for about two seconds you'll
   see the mod's total playtime ("12h 34m", "47m", "2d 5h 12m") and when
   it was last played ("today", "yesterday", "3 days ago", or an actual
   date for older sessions). See PLAYTIME TRACKING below for details.


Q: What happens if I right-click a mod row?
A: A context menu appears with three options:
       Backup Saves - immediate snapshot of this mod's save folder
       Re-zip       - package the mod folder back into a .zip in <D2R>\mods\
       Uninstall    - delete the mod from <D2R>\mods\ (with confirmation;
                      runs a save backup first so your characters aren't lost)
   See README.txt > RIGHT-CLICK MOD MENU for details on each.


--------------------------------------------------------------------------------
  PLUGIN MANAGER  (v1.3+, extended in v1.4)
--------------------------------------------------------------------------------


Q: What is the Plugin Manager?
A: The Plugins button in the LOADER OPTIONS section opens a window listing
   every plugin (.dll) and patch (.json) the launcher found for the
   currently-selected mod. These sit either in your D2R install's global
   d2rloader\ folders (available to every mod) or inside the mod's own
   d2rloader\ folders (mod-local). The Plugin Manager lets you toggle each
   one on or off for that mod.


Q: What's the difference between a plugin and a patch?
A: Plugins are .dll files that hook into the game's code. Patches are .json
   files that describe memory modifications D2RLoader applies at runtime.
   From the launcher's perspective they're the same thing - both live in
   the d2rloader\ tree, both can be enabled/disabled, both can have friendly
   names. The file extension shown in parentheses on each row tells you
   which is which.


Q: What's the difference between Global and Mod entries?
A: Global entries live in <D2R>\d2rloader\plugins\ and <D2R>\d2rloader\patches\
   and apply to every mod that doesn't override them. Mod entries live in
   <D2R>\mods\<ModName>\d2rloader\plugins\ and ...\patches\ and only affect
   that one mod. The Plugin Manager shows them under two section headers so
   you can tell them apart at a glance. Toggling an entry off moves its file
   into a sibling "Disabled\" folder, so nothing is deleted - you can flip
   it back on later.


Q: My plugins were in <D2R>\plugins\ and now they don't show up. What
   happened?
A: D2RLoader beta 1.0 moved plugin discovery to <D2R>\d2rloader\plugins\.
   Move your .dll files there (and any .json patches to
   <D2R>\d2rloader\patches\) and they'll reappear. Same for mod-local
   plugins: <D2R>\mods\<Mod>\<Mod>.mpq\Plugins\ is no longer scanned by
   either D2RLoader or the launcher; use
   <D2R>\mods\<Mod>\d2rloader\plugins\ instead. This also fixes the
   problem where mods shipping a compressed .mpq file (rather than an
   exposed .mpq folder) couldn't have plugins at all.


Q: What is plugin_config.json?
A: An optional file a mod author can drop into their mod's root folder
   listing exactly which plugins and patches the mod is designed to run
   with. When a mod has one:
     * The Plugin Manager shows the authored list as a read-only inventory -
       no toggles, since the author has already made the choices.
     * The launcher moves any of your globally-enabled plugins and patches
       to their Disabled folders for the duration of that mod's session, so
       nothing outside the author's curated list gets loaded.
     * Missing entries from the list are auto-recovered from the global
       or Disabled folders when possible (globals get copied so other mods
       still have them; disabled entries get moved back).
   The same recovery + globals sweep also runs the moment you press PLAY,
   so there's no way to accidentally launch with stale globals enabled.


Q: Can plugin_config.json list both .dll and .json files?
A: Yes - put them all in the single "plugins" array:
       { "plugins": ["someplugin.dll", "somefix.json"] }
   The launcher routes each entry to plugins\ or patches\ based on its
   extension.


Q: The Plugin Manager says "<Author> has selected to disable plugins for
   <Mod>". What does that mean?
A: The mod ships a plugin_config.json with an empty plugin list — the
   author has explicitly declared that this mod runs without any plugins
   or patches. Your globals are temporarily moved to Disabled while that
   mod is active. If you want to override this you can delete or edit the
   mod's plugin_config.json — but that's the author telling you their mod
   isn't built to play nicely with any plugin, so it may not run as
   expected.


Q: I toggled a global plugin on for one mod. Why did it disappear when I
   selected a different mod?
A: Global entries are shared across mods by default, but if the mod you
   switched TO has a plugin_config.json that doesn't include that entry,
   the launcher moves it to the global Disabled folder. It'll come back
   automatically the next time you select a mod that expects it, or you
   can move it out of Disabled manually.


Q: A plugin I know I have installed isn't showing up in the Plugin Manager.
   Where did it go?
A: Three likely reasons:
   1. It's in the old <D2R>\plugins\ location. Move it to
      <D2R>\d2rloader\plugins\ (see the path question above).
   2. The current mod has a plugin_config.json that doesn't list your
      plugin - only configured entries appear in that mode.
   3. The file is sitting in a "Disabled\" folder (either global or
      mod-local). Move it out to the active folder and click Refresh in
      the Plugin Manager.


Q: Can I give my plugins and patches nicer display names?
A: Yes - v1.3 added a launcher-wide plugin_manifest.json that maps
   filenames to friendly display names. It covers both .dll plugins and
   .json patches. There are two ways to edit it:
     * Right-click any row in the Plugin Manager and pick "Rename..."
       to enter a display name. Saves immediately.
     * Open plugin_manifest.json in a text editor (it lives beside
       Angiris.exe) and fill in names alongside the filename keys the
       launcher already pre-populated for you.
   Once set, the friendly name shows everywhere that file appears, in the
   form "Friendly Name (filename.dll)" or "Friendly Name (filename.json)".


Q: I edited plugin_manifest.json by hand. Why didn't my changes stick?
A: The launcher rewrites plugin_manifest.json when the Plugin Manager
   closes (to add newly-discovered files as blank entries). It preserves
   any names you set, but if the file's JSON is malformed the launcher
   falls back to defaults. Make sure your edits are valid JSON before
   closing the Plugin Manager. Editing outside a launcher session (with
   the launcher closed) is always safe.


Q: I don't see (G) or (M) tags on my plugin rows any more. Where did they
   go?
A: v1.3 replaced the inline (G) / (M) tags with dedicated "Global plugins"
   and "Mod plugins" section headers. Same information, less visual noise.


Q: How do I install a plugin? (v1.6)
A: Drag the plugin's zip onto the launcher. Drop it on the MAIN window to
   install it globally (for every mod), or drop it on the PLUGIN MANAGER
   window to install it into the currently-selected mod. The launcher reads
   the zip's plugin_info.json and puts each file where it belongs - the .dll
   into plugins\, config into config\, any readme into the readmes store,
   and so on. No manual copying.

Q: I dropped a plugin and got asked about overwriting. What are my options?
A: If a plugin with that name is already installed you'll be asked before
   anything is replaced. For a plugin with config you can choose to replace
   just the DLL, just the config, both, or cancel. Whenever a config file
   (or a patch, or an excel .txt) is overwritten, the old one is saved
   alongside it as <name>.old so you can copy your settings back.

Q: I dropped a plugin but nothing happened / it said it wasn't authorized.
A: If the selected mod ships a plugin manifest (plugin_config.json), it only
   accepts the plugins and patches the mod author sanctioned. A plugin that
   isn't on that list is declined with a short notice naming the mod (and
   author, if given). Drop it on the MAIN window instead to install it
   globally, or ask the mod author to add it to their manifest.

Q: How do I install a patch? (v1.6)
A: Even easier - just drop the patch's .json file straight onto the launcher
   (main window = global, Plugin Manager = the selected mod). No zip, no
   manifest needed. You can also drop a zip that contains one or more .json
   patches and the launcher will extract just the JSON files to the patches
   folder. Existing patches prompt before overwriting and keep a .old backup.

Q: I re-installed a plugin I had disabled and now it's... still disabled?
A: That's intended (v1.6). If a plugin is installed but toggled off (sitting
   in the Disabled\ folder), dropping it again overwrites the disabled copy
   in place rather than creating a fresh enabled one. A re-install won't
   silently turn something back on that you deliberately turned off, and you
   won't end up with two copies.

Q: What's the READMEs button in the Plugin Manager?
A: If a plugin shipped a readme, it's viewable here (v1.6). Click READMEs for
   a picker of every plugin that has one, or right-click a plugin row and
   choose "Open README". Readmes are stored globally so they're always found
   regardless of which mod a plugin was installed into.

Q: I'm a mod author - how do I make a plugin zip the launcher understands?
A: Put a plugin_info.json in the zip describing where each file goes. The full
   format (including custom destPath locations and the required fields) is in
   plugin_info_GUIDE.md that ships alongside the launcher. Patches don't need
   a manifest at all - a bare .json is enough.


--------------------------------------------------------------------------------
  ABOUT MODAL & D2RLOADER UPDATES
--------------------------------------------------------------------------------


Q: The About button used to open README.txt in Notepad. What happened?
A: v1.4.1 replaced that with a proper About window. It shows your Angiris
   version and your installed D2RLoader version, gives you a one-click
   D2RLoader download, and opens README and FAQ inside the launcher
   itself instead of handing them to an external editor.


Q: How do I read the README or FAQ now?
A: For the FAQ, just click Help in the left rail - it opens the FAQ in a
   scrollable reader inside the launcher, with a Discord link at the
   bottom. For the README, use About -> the README icon button. Both
   scroll with the mouse wheel; Close or Esc dismisses them. The .txt
   files are still sitting next to the launcher if you'd rather open them
   yourself.


Q: The Help button used to open FAQ.txt in Notepad. What happened?
A: As of v1.5 it opens the FAQ in a reader inside the launcher instead,
   styled to match the rest of the UI. Below the text is a "Need More
   Help?" prompt with a Discord button for the community server.


Q: Why does the About window say "D2RLoader — Not detected"?
A: One of three things: D2RLoader.exe isn't in your D2R folder, your D2R
   folder isn't set yet (use the "..." button in the LOADER OPTIONS
   header), or that particular D2RLoader build doesn't carry a version
   resource for the launcher to read. The launcher says "Not detected"
   rather than guessing.


Q: What does the "Latest D2RLoader" button do?
A: Downloads the current D2RLoader release from d2rloader.net and
   installs it into your D2R folder, then updates your D2RLoader.toml
   with any new settings the release added. Your existing settings are
   kept - see the config question below.


Q: I clicked download and it told me to close D2R. Why?
A: A running game or loader holds its files open, so an update would
   fail partway and leave you with a half-updated install. The launcher
   offers to close them for you - say Yes and it closes the game, waits
   for the file locks to release, and starts the download automatically.
   Any unsaved game progress is lost, since this is a hard close.


Q: What if I launch the game while the download is running?
A: The launcher checks again just before it writes anything. If the game
   came up in the meantime it stops and tells you, without touching your
   install. Close the game and click the button again.


Q: What is the "Verifying" step?
A: d2rloader.net publishes a SHA-256 checksum for each release. After
   downloading, the launcher hashes the file and compares it against
   that published value. If they don't match, the install stops and
   nothing is written to your game folder - a mismatch means the file
   isn't what the official release should be. If the checksum can't be
   read at all (site down, page changed), the install continues and
   notes it in assets\d2rloader_install.log.


Q: Will updating D2RLoader wipe my D2RLoader.toml settings?
A: No. Your toml is preserved and then amended. Values you already have
   are never changed - if you set show_ground_sockets = true and the new
   release defaults it to false, you keep true. Only genuinely new keys
   and sections get appended, in a block marked

       # ---- Added by Angiris Launcher (new D2RLoader keys) ----

   Your original is backed up to D2RLoader.toml.bak first.


Q: After an update my toml has the same section header twice. Is that
   broken?
A: No. The appended block re-states its section headers, so you may see
   e.g. [d2rloader] appear a second time near the bottom. TOML parsers
   merge duplicate section headers, so D2RLoader reads it correctly.
   It's the tradeoff for a merge that never edits a line you already
   had. You can tidy it by hand if you like.


Q: What is the gold "D2RLoader Update Available" text?
A: On startup the launcher compares your installed D2RLoader against the
   current release listed on d2rloader.net. If yours is older, that
   notice appears above the LOADER OPTIONS header. Click it to open the
   About modal, where the download button will update you.


Q: I know there's a newer D2RLoader but I don't see the notice.
A: The notice only appears when the launcher can confirm BOTH versions
   and the site's is genuinely newer. If D2RLoader isn't installed, the
   version check couldn't reach the site, or your build has no version
   stamp, nothing is shown rather than a claim it can't back up. Check
   assets\d2rloader_check.log to see what it found. You can always open
   About and download regardless of whether the notice is showing.


Q: Does 1.0.1 vs 1.0.1-beta count as an update?
A: No. Pre-release suffixes are stripped before comparing, so those two
   are treated as the same version and no notice appears.


--------------------------------------------------------------------------------
  UI SCALE
--------------------------------------------------------------------------------


Q: Can I pick a UI scale directly instead of clicking through the toggle?
A: Yes - add this to assets\user_layout.json:

       { "scale_as_dropdown": true }

   The Scale control becomes a dropdown listing every preset available
   at your DPI, so it's one click to any of them. The control restacks
   to put the "SCALE" label above the value box (matching the On Launch
   column) and widens the box so three-digit values aren't cramped.
   Leave the setting out, or set it false, to keep the cycle toggle.


Q: I added scale_as_dropdown but nothing changed.
A: Check the JSON is valid - a stray comma or missing brace makes the
   launcher fall back to defaults for the whole file. The file lives at
   assets\user_layout.json next to the launcher exe, and the setting
   takes effect on the next launch.


Q: The launcher opened so large I can't reach the Scale control to fix
   it. What do I do?
A: Update to v1.5 and just launch it - it corrects itself. Earlier
   versions offered scale options that didn't fit smaller screens (on
   1080p, the 127% option made the window 273px taller than the desktop),
   and since the Scale control sits near the bottom of the window,
   choosing one put the control out of reach permanently. v1.5 checks
   every scale against your actual monitor at startup and steps it down
   to one that fits.

   If you're stuck on an older build, delete launcher_config.json (next
   to the launcher exe) to reset the scale. You'll lose your saved D2R
   path and preferences, but the window will be usable again.


Q: Why do I get different scale percentages than someone else on the same
   Windows scaling?
A: Because resolution matters as much as Windows scaling. A 1080p and a
   4K screen both set to 150% report the same scaling to Windows, but the
   4K screen has far more room. The options you get:

                     Windows 100%     Windows 125%     Windows 150%
       1080p          75/85/100        50/65/75         50/65/75
       1440p          100/115/127      75/85/100        65/75/85
       4K             100/115/127      85/100/115       75/85/100

   Your Windows scaling picks the set; your resolution shifts it down if
   that set wouldn't fit on screen.


Q: My scale changed by itself after I updated / moved the window to
   another monitor.
A: The launcher won't apply a scale whose window doesn't fit the monitor
   it's on - it drops to the largest one that does. Moving from a large
   monitor to a smaller one will reduce it. Note that it doesn't go back
   up automatically when you return to the larger monitor; set it again
   from the Scale control.


Q: Why did my window jump to the top of the screen when I maxed the UI
   scale?
A: At the highest scale for your DPI, a fully expanded window (with the
   modding area open) can be taller than your screen. Rather than make
   you drag the window up before you can use it, the launcher pins the
   top edge to the top of your monitor's work area - but only when the
   expanded window wouldn't otherwise fit. At any other scale, or if it
   already fits, your window stays exactly where you left it.


Q: My minimize/close buttons look plain and drawn rather than the normal
   artwork.
A: That's the fallback rendering, which means btn_minimize.png or
   btn_close.png is missing from your assets folder or failed to load.
   The buttons still work. Restoring those files from a fresh download
   brings the artwork back.


--------------------------------------------------------------------------------
  LOADER OPTIONS  (BASIC + DEVELOPER)
--------------------------------------------------------------------------------


Q: What are the Loader Options?
A: The bottom-left panel labelled LOADER OPTIONS holds settings that get
   written straight into D2RLoader.toml in your D2R install folder. These
   are global settings - they apply to every mod, not just the selected
   one. The panel is three buttons: Basic Options, Developer Options,
   and Plugins.


Q: What's in Basic Options?
A: Six settings:
     Show Sockets         - shows socket counts on ground items
     Show Item Level      - shows item levels
     Respec Skill/Stats   - enables in-game respec
     Stash Tabs           - extra shared stash tabs (0-16 dropdown)
     Material Limit       - stack limit for crafting materials (text box)
     Show TCP/IP Button   - shows the TCP/IP option in the game menu


Q: What's in Developer Options?
A: Debug + logging settings most players will never need:
     Enable Console          - D2RLoader's debug console
     Assert Dialog Message   - shows assert dialogs instead of silently failing
     Enable Logging          - master toggle for the log system
   Plus seven log-detail toggles (JSON Resources, Widget Panel Creation,
   Excel File Loaded, True and Open Type Fonts, UI Sprites Creation, Chat
   Messages, Models Creation). These are greyed out and do nothing unless
   Enable Logging is on.


Q: Why is Material Limit a text box instead of a dropdown?
A: The range is 0-255, which is too many entries for a comfortable menu.
   Type a number and click away (or press Tab) - the value saves on
   focus-loss. Out-of-range values snap to the nearest bound.


Q: The Material Limit note says "Default = 99, Max = 255". What happens
   above 99?
A: D2RLoader accepts up to 255, but its own config documentation flags
   values above 99 as producing undefined behaviour. Use them at your
   own risk. The launcher lets you set anything in 0-255 and doesn't
   second-guess you.


Q: Why is there no Save button on the Options modals?
A: Changes apply immediately - every toggle and value writes to
   D2RLoader.toml the moment you change it. There's nothing to save
   because D2RLoader only reads the toml when it launches, so there's
   no live session state to preserve or roll back. Just close the
   modal when you're done.


Q: I changed a Loader Option but it doesn't seem to take effect. Why?
A: D2RLoader reads the toml only when it starts, so the change applies
   the NEXT time you press PLAY, not to a session that's already running.
   Exit D2R and relaunch.


Q: Will changing these wipe my other D2RLoader.toml settings?
A: No. The launcher edits only the specific keys it surfaces and leaves
   everything else - including your comments and any keys it doesn't
   recognize - exactly as it found them.


Q: The launcher keeps resetting default_mod and skip_title_screen. Why?
A: Those two keys would bypass the launcher entirely - default_mod tells
   D2RLoader to auto-launch a specific mod without showing the picker,
   and skip_title_screen bypasses the D2R title screen. Angiris resets
   both on every start so it stays the entry point for mod selection.
   If you want D2RLoader to auto-launch without the launcher, run
   D2RLoader.exe directly instead of through Angiris.


--------------------------------------------------------------------------------
  PLAYTIME TRACKING
--------------------------------------------------------------------------------


Q: How does the launcher know how long I've played?
A: When you click PLAY, the launcher watches for D2RLoader.exe or D2R.exe to
   start. When it sees the process, the clock starts. When the process exits,
   the elapsed time is added to that mod's cumulative total. Time spent in
   the launcher itself - browsing mods, tweaking flags - is NOT counted.


Q: I just launched a mod but the playtime didn't update.
A: The tooltip caches the value until you re-hover or restart the launcher.
   Move off the row and back onto it after a session to see the updated
   number. The data file (assets\playtime.json) is always current though -
   the UI tooltip just has a small cache.


Q: I uninstalled and reinstalled a mod - did I lose my playtime?
A: No, as long as you reinstall it into the same folder name. Playtime is
   keyed by folder name (not by anything inside the mod), so the history
   reattaches automatically.


Q: Can I reset playtime for one mod?
A: Yes - close the launcher, open assets\playtime.json, delete that mod's
   entry, save the file, and relaunch. The mod's playtime resets to 0 and
   its "last played" is cleared.


Q: Can I reset all playtime data?
A: Delete (or empty) assets\playtime.json. The launcher recreates it on the
   next mod launch.


Q: Why doesn't the timer count time I spent in the launcher figuring out
   what to play?
A: That'd inflate every mod's number with browsing time. The launcher
   intentionally only counts time while D2R is actually running - the
   metric is "time spent IN the mod", not "time looking AT the mod".


--------------------------------------------------------------------------------
  SAVE BACKUPS
--------------------------------------------------------------------------------


Q: What's a save backup?
A: A full copy of a mod's save folder, taken at a specific moment. The
   snapshot goes into a "backups\" subfolder next to the original save data,
   named with the timestamp (YYYY-MM-DD_HHMMSS). See README.txt > SAVE
   BACKUPS for the exact paths.


Q: When does the launcher take a backup?
A: Three triggers:
   1. You right-click a mod and pick "Backup Saves"   (manual)
   2. You drop a mod zip onto the launcher and pick "Overwrite" in the
      conflict dialog (auto - the existing mod is about to be wiped)
   3. You right-click a mod and pick "Uninstall"      (auto)


Q: How many backups does the launcher keep?
A: The five most recent per mod. When you take a sixth, the oldest one is
   deleted automatically. This keeps your backups folder from growing
   forever while still giving you meaningful history.


Q: How do I restore from a backup?
A: Manually. Open the backups\ folder (it's next to the live save folder
   for that mod, under %USERPROFILE%\Saved Games\Diablo II Resurrected\Mods\),
   pick the timestamped folder you want, and copy its contents up one level
   to replace the current saves. The layout inside the snapshot mirrors the
   live folder, so it's a straight copy.


Q: Can I disable automatic backups?
A: Not via the UI. If you really don't want them, the safest workaround is
   to use Update mode (not Overwrite) on installs - Update preserves your
   files. For Uninstall, there's no opt-out; the backup is a safety net for
   your characters.


Q: The backup folder is taking up too much space.
A: Rotation should keep it bounded (5 snapshots max per mod), but if your
   save folder itself is huge each snapshot will be huge too. You can
   manually delete older snapshots; the launcher only manages the rotation
   when a new one is created.


--------------------------------------------------------------------------------
  LAUNCHER SELF-UPDATES
--------------------------------------------------------------------------------


Q: What's the gold-glowing version label in the left rail?
A: That's the launcher telling you a newer launcher release is available
   on GitHub. Click it to open the update prompt.


Q: I clicked the version label - what are the three buttons?
A: Update            - download and install the new version in place
   Skip This Version - dismiss for this specific version (remembered; the
                       prompt won't reappear until a NEWER version ships)
   Ignore            - dismiss just this once (the prompt comes back next
                       launch)


Q: I clicked Update and a popup appeared. What's happening?
A: The launcher is installing the new version in place. The popup shows
   three statuses:
       Downloading       - fetching the release zip from GitHub
       Updating          - extracting and copying new files
       Complete          - install done, ready to restart
   When you see Complete, the Restart button enables (after a half-second
   delay so accidental clicks don't fire). Click it to spawn the new
   launcher and close the running one.


Q: The main launcher window vanished during the update!
A: That's intentional. The main window has to hide so the asset files it
   has loaded (PNG images, fonts) get released and can be overwritten. The
   small update popup is your status indicator during the install.


Q: The Restart button never appeared. The popup is stuck on "Updating".
A: Something failed in the install. Open assets\last_update_install.log
   and look for the most recent block - it'll show every file that was
   copied (with paths) and any that failed. Common causes:
       err=1224 (USER_MAPPED_FILE)   - a file is memory-mapped by the
                                       running launcher and can't be
                                       overwritten. Fonts hit this.
       err=5    (ACCESS_DENIED)      - permissions issue, or antivirus
                                       blocked the copy
       err=32   (SHARING_VIOLATION)  - another process has the file open


Q: Why is there an Angiris.exe.old file in my launcher folder?
A: Self-update artifact. The old launcher exe gets renamed to .old during
   the install (because Windows won't let you overwrite a running .exe).
   The NEXT time you launch the new version it deletes the .old file
   automatically. If you see it, just launch the launcher once and it
   should clear up.


Q: I see .old left over even after launching - should I delete it?
A: You can delete it manually any time it's not the active launcher. The
   automatic cleanup retries five times with brief delays and falls back to
   scheduling it for deletion on the next Windows reboot. If something
   really has it locked (antivirus is the usual culprit), reboot Windows
   and it'll be cleared.


Q: Will updating the launcher replace my fonts / config / playtime data?
A: Update replaces: the .exe, all PNG assets, JSON data files SHIPPED in
   the release (e.g. CHANGELOG, README, FAQ), and any docs.
   Update does NOT replace: .ttf font files (Windows holds an internal
   mapping for the active font that can't be released mid-process), or
   user-generated state like launcher_config.json, assets\playtime.json,
   assets\seeds.json's "recent" array, or your per-mod launcher_mod_cfg.json
   files (those live in your mods folders, untouched by the install).


Q: My font got out of date with launcher updates - now what?
A: Drop the new .ttf into assets\fonts\ manually. The launcher picks it up
   on next start. (In practice, fonts almost never change between launcher
   releases.)


Q: Can I roll back to the previous launcher?
A: If the Angiris.exe.old file is still in your folder, rename Angiris.exe
   to something else (Angiris.exe.bad), then rename Angiris.exe.old to
   Angiris.exe. You're back on the previous version. If .old has been
   deleted, you'll need to download the older release from the GitHub
   releases page manually.


--------------------------------------------------------------------------------
  LAUNCH OPTIONS / FLAGS
--------------------------------------------------------------------------------


Q: What do the six flag toggles do?
A: They become command-line arguments passed to D2RLoader.exe:
       Use Txts    -> -txt              (loads modded .txt files)
       No Sound    -> -ns               (disables all audio)
       Window      -> -w                (windowed instead of fullscreen)
       Skip Intro  -> -skiplogovideo    (bypasses the intro logos)
       Respec      -> -enablerespec     (allows free skill unlimted respec)
       Reset Maps  -> -resetofflinemaps (re-rolls all map seeds at launch)
   See the Seed row below the flag grid for the seventh arg (-seed).


Q: Why can't I turn off "Use Txts"?
A: The current version of D2RLoader requires -txt to be on, so the launcher
   locks that flag on (it's dimmed and can't be toggled). If a future D2RLoader
   removes the requirement, this lock will be lifted.


Q: My flags reset every time I switch mods.
A: They don't reset - they're saved per-mod in each mod's
   "Launcher Files\launcher_mod_cfg.json". Switching mods loads that mod's
   saved flags; switching back loads the original ones. This is intentional.


Q: Can I see the full launch command before clicking PLAY?
A: Yes - the launch-command preview in the Launch Options panel shows exactly
   what's about to be passed to D2RLoader.exe, and updates live as you toggle
   flags or type into the Seed field. The preview box auto-resizes between
   1, 2, and 3 text rows depending on how much wraps.


--------------------------------------------------------------------------------
  SEED  (-seed)
--------------------------------------------------------------------------------


Q: What is the Seed row for?
A: It controls D2R's -seed command-line argument, which forces a specific
   map / drop seed for the game session. The row has three parts:
       [checkbox]   "Seed"
       [text input]  - type a numeric seed value (digits only)
       [v] arrow     - opens a dropdown of saved seeds (presets + recents)
   The seed is per-mod (it goes into the mod's launcher_mod_cfg.json), and
   when the checkbox is on it's appended as "-seed VALUE" at the END of the
   launch command, after -skiplogovideo.


Q: Where do the dropdown entries come from?
A: From assets\seeds.json next to the launcher. The file has two arrays:
   * "seeds"  - author-defined presets you can name (e.g. "Speedrun 1.13c")
   * "recent" - the launcher's rolling 3-slot history of values YOU typed
   Recents show at the TOP of the dropdown (newest first, labeled
   "Recent3", "Recent2", "Recent1"); presets follow below.


Q: How do recents work?
A: When you type a value into the Seed input and commit it (press Enter,
   click outside the box, or open the arrow dropdown), the launcher saves
   that value to assets\seeds.json under "recent". Up to 3 are kept. When a
   4th gets added the oldest one falls off:
       before:  Recent1=A  Recent2=B  Recent3=C   (C is newest)
       type D:  Recent1=B  Recent2=C  Recent3=D   (A fell off)
   Values that already match a preset or an existing recent are NOT added
   again (no duplicates, no reshuffling).


Q: What keys work in the Seed text input?
A: Digits 0-9 type normally; everything else is filtered out (no letters,
   no separators, no decimal points). Standard text-input controls all work:
       Left / Right            - move caret one position
       Home / End              - jump to start / end
       Backspace / Delete      - remove a character
       Shift + Left / Right    - extend selection
       Shift + Home / End      - select to start / end
       Click in the input      - position caret at click point
       Click + drag            - drag-select a range
       Ctrl+A                  - select all digits in the input
       Ctrl+C                  - copy selection (or whole value if none)
       Ctrl+X                  - cut selection
       Ctrl+V                  - paste from clipboard (digits only - any
                                 non-digit characters in the pasted text
                                 are filtered out)
       Enter                   - commit + leave the input
       Esc                     - leave the input without committing to
                                 recents (the value stays, just isn't saved
                                 to seeds.json)


Q: I selected a seed but my checkbox is still off. Will -seed be passed?
A: No. The checkbox is the master switch. When it's off, the typed/selected
   value is preserved (so you can prepare it), but -seed is NOT appended.
   Toggle the checkbox on to actually use the value.


Q: Why is the Seed text greyed out?
A: That means the checkbox is off (the value won't be used). The text is
   still readable but rendered dim to make the inactive state obvious.
   Click the checkbox to enable.


Q: Why doesn't a value I picked show up in Recents?
A: Only values you TYPE get added to Recents. Picking an existing entry from
   the dropdown (whether a preset or a recent) doesn't create a new Recent
   entry - it's already in the list.


Q: Can I delete a Recent entry?
A: Not from the UI. Open assets\seeds.json and remove the entry from the
   "recent" array. Or just type new values - the oldest one drops off
   automatically once you've added 3 more.


Q: How do I add my own presets to the seeds dropdown?
A: Edit assets\seeds.json. Each entry has a name (what the dropdown shows)
   and a value (what gets passed to -seed):

       {
         "seeds": [
           {"name": "Speedrun 1.13c", "value": "1234567"},
           {"name": "Holy Grail Run", "value": "999"}
         ],
         "recent": []
       }

   Restart the launcher to pick up changes. Presets pass through the
   launcher untouched; only the "recent" array gets rewritten.


Q: My seeds.json is missing or corrupted - now what?
A: If the file is missing or has no "seeds" array, the launcher falls back
   to a small built-in starter list (Random/Standard/Speedrun A/Speedrun B)
   so the dropdown still works. The fallback is overwritten as soon as you
   drop a real seeds.json in.



--------------------------------------------------------------------------------
  TOOLBAR  (SCALE / FONT / COLOUR)
--------------------------------------------------------------------------------


Q: What's the row of four controls under the mod list?
A: That's the appearance toolbar:
       On Launch - 3-state slider that changes what happens to the launcher when you launch a mod (Minimize it, close it or have it stay on screen)
       Scale  - 3-state slider that cycles through three UI size presets
       Font   - dropdown of the bundled .ttf fonts in assets\fonts\
       Colour - dropdown of 8 gold/red/green accent colors
   Each saves immediately to launcher_config.json and applies live.


Q: How does the Scale slider work? Why does mine show different percentages?
A: The slider has three positions: 0 (small), 1 (medium), 2 (large). The
   ACTUAL percentages depend on your Windows display scaling:
       Windows at 100%   -> 100%, 115%, 127%
       Windows at 150%+  -> 75%,  85%,  100%
   The launcher detects your system DPI and picks whichever 3-preset set
   keeps the window from overflowing your screen. Click the slider to
   cycle through the three; the text box above shows the active value.


Q: Why did my UI scale reset when I changed Windows display settings?
A: Between sessions, the launcher checks whether your system DPI changed
   since last close. If it did, the saved ui_scale resets to 1.0 because a
   scale that looked right at 100% can leave the window way too small at
   150% (or off-screen at 175%). Pick the size you want from the slider
   and it'll stick for that DPI.


Q: The fonts in the dropdown look the same / I don't see Cinzel.
A: The dropdown reads every .ttf in assets\fonts\. If you don't see one,
   the file isn't there. Names are abbreviated for display (e.g.
   "Cinzel-Bold" -> "Cin-Bol") but it's the same family. See README.txt >
   TYPOGRAPHY for the bundled set.


Q: I picked a different font and now everything is huge / clipped.
A: Different fonts have different "cell heights" at the same em size -
   Cinzel Black is much taller than Exocet Blizzard at the same nominal
   size. The launcher caps every user font's rendered cell height at
   Exocet's (its reference family), so this should be rare. If you still
   see clipping, try a smaller Scale preset or pick a less display-heavy
   font.


Q: The Colour dropdown changed text but my mod row borders are still gold.
A: The accent color drives every gold-token paint site (text, chevrons,
   highlights). Some chrome (the engraved frame, the gem ornament, the
   stone backgrounds) is part of the artwork itself and doesn't follow the
   token. That's intentional - the art is meant to read as bronze
   regardless of the accent color.


Q: Black accent is hard to read.
A: Yeah, it is. The "Black" preset is included for completeness but it
   trades readability for a dark-mode look. Pick "Pale Gold" or "Bright
   Gold" for the most legible text.


--------------------------------------------------------------------------------
  UPDATES (FOR MODS)
--------------------------------------------------------------------------------


Q: What's the gold arrow badge on a mod row?
A: It means an update is available for that mod (the mod opted in to update
   checking via modinfo.json). The Mod Description panel shows the version
   change and a "[Details]" link.


Q: I clicked "[Details]" / "Update Selected Mod" and it just opened a webpage.
A: That's by design. The launcher points you at the mod's source page so you
   can download and install the update yourself. It deliberately does NOT
   auto-download or auto-install mod updates, because it can't verify the
   integrity of files it didn't build. Review the update at the source, then
   install it the way the author intends.
   (Note: the LAUNCHER itself CAN auto-install its own updates - see LAUNCHER
   SELF-UPDATES above. Different policy because the launcher's source is one
   trusted repo.)


Q: How does a mod opt in to update checking?
A: The author adds one of these to modinfo.json:
       "update_github":   "owner/repo"
       "update_manifest": "https://.../version.json"
   See README.txt > UPDATES.


--------------------------------------------------------------------------------
  THE BOTTOM PANEL
--------------------------------------------------------------------------------


Q: What's the little arrow under the mod list?
A: It expands/collapses the bottom panel. Down arrow = collapsed (click to
   open); up arrow = expanded (click to close). The window grows taller when
   open and shrinks back when closed. These options are intended for modding use
   and not for players.


Q: How do the "Edit TXT / Sprite / JSON / Models / Textures / Particles"
   buttons know where my tools are?
A: The first time you click one, the launcher searches your tools folder for
   the relevant .exe (resolving .lnk shortcuts) and caches the path in
   launcher_config.json. Later clicks are open the application immediately


Q: A tool button said it couldn't find the tool.
A: Either the tool isn't in your tools folder, or it has a different filename
   than expected. When prompted, click to locate the .exe manually; the
   launcher caches your choice for next time.


Q: Where do I download these tools?
A: Open the DOWNLOADS section in the bottom panel:
       Text Editor
       Sprite Editor
       Visual Basic Code
   Each opens a download page in your browser.


Q: What do the REFERENCES and TUTORIALS sections do?
A: REFERENCES opens community modding resources in your browser (File
   Guides, The Phrozen Keep, Amazon Basin, Paul Siramy's site). TUTORIALS
   opens step-by-step guides - level creation, larger stash, runewords,
   items and sets, superuniques, and a beginner's guide - with more added
   over time.


Q: How does the bottom panel work now?
A: Click the arrow under the center column to open it. It shows four
   sections - REFERENCES, TOOLS, DOWNLOADS, TUTORIALS. Click any section
   and a small window lists its items; click an item to open the link or
   launch the tool. Short lists are one column, longer ones two.

A: Not by dragging - the size is fixed for the current UI scale. To change

--------------------------------------------------------------------------------
  CONFIG / DATA
--------------------------------------------------------------------------------


Q: Where are my settings stored?
A: Six places:
   * launcher_config.json  (next to the launcher exe) - global settings
   * plugin_manifest.json  (next to the launcher exe) - plugin/patch names
   * assets\seeds.json     (next to the launcher exe) - seed presets + recents
   * assets\playtime.json  (next to the launcher exe) - per-mod playtime
   * <mod>\Launcher Files\launcher_mod_cfg.json       - per-mod flags + seed
   * D2RLoader.toml        (in your D2R folder)       - the loader settings
                                                        surfaced by the Basic
                                                        and Developer Options
                                                        modals
   All are plain text and safe to inspect.

   Three of them - user_layout.json, seeds.json, and playtime.json - are
   PRESERVED when the launcher updates itself, so your custom layout,
   seed history, and playtime totals aren't reset by an update.


Q: How do I reset all launcher settings?
A: Quit the launcher and delete launcher_config.json. To also reset per-mod
   flags + seeds, delete the launcher_mod_cfg.json files inside each mod's
   Launcher Files folder. To clear the seed recents history, edit
   assets\seeds.json and empty the "recent" array. To clear all playtime
   data, delete assets\playtime.json. To reset plugin/patch display names,
   delete plugin_manifest.json (the launcher will re-create it with blank
   entries next time you open the Plugin Manager). (Deleting any of these
   won't touch D2RLoader.toml.)


Q: The launcher won't start.
A: Make sure the launcher exe and the assets\ folder are together, and that
   you're running from a folder you have write access to (it writes
   launcher_config.json next to itself). Re-extract from the archive if files
   are missing.


Q: What are the .log files in my assets\ folder?
A: Diagnostic logs from launcher self-updates:
       last_update_check.log    - what GitHub returned the last time the
                                  launcher checked its own version (URL,
                                  version tag, response body)
       last_update_install.log  - per-file copy results from the most recent
                                  self-update install attempt (appended, so
                                  you can see history)
   Safe to delete - they regenerate next time. Useful if you're troubleshooting
   a failed self-update.


--------------------------------------------------------------------------------
  MOD AUTHORS
--------------------------------------------------------------------------------


Q: How do I make my mod look nice in the launcher?
A: Edit your modinfo.json to include the optional fields:

       {
         "name":        "MyMod",                  (required - D2R reads this)
         "savepath":    "MyMod\",                 (required - D2R reads this)
         "title":       "My Awesome Mod",         (optional - display name)
         "version":     "1.2.3",
         "author":      "Your Name",
         "description": "Shown in the Mod Description panel",
         "banner":      "Banner.jpg",             (optional - row background)
         "docs":        "./docs/manual.pdf",      (optional - Docs button)
         "website":     "https://yourmod.com",    (optional - Website button)
         "discord":     "https://discord.gg/x",   (optional - Discord button)
         "update_github":   "owner/repo"          (optional - update checking)
       }

   Then create a "Launcher Files\" subfolder inside your mod folder and drop
   your banner image there. See README.txt > MOD METADATA.


Q: What size should my banner be?
A: Wide. The row is much wider than it is tall (96 x 600), and the image
   is cropped to "cover" the row. A wide banner crops cleanly; a tall or square
   one loses its top and bottom. You can bake the name/author/version into the
   art if you want full control. See README.txt > BANNERS.


Q: How do I set my mod up so that the launcher checks for updates?
A: See README.txt > HOW TO SET UP MY MOD FOR UPDATE CHECKS. It is the last section
   of the README, right before the CREDITS.


--------------------------------------------------------------------------------
  LOGS TOOL  (v1.6)
--------------------------------------------------------------------------------


Q: What does the Logs button do now?
A: It opens an in-launcher grid of the files in <D2R>\logs\ (crash logs,
   d2rloader.log, etc.) instead of opening an Explorer window. Each file
   shows as an icon with its name beneath it.

Q: How do I send a log to someone for help?
A: Left-click the log's icon. That copies the actual file to your clipboard,
   so you can paste it (Ctrl+V) straight into Discord (or an Explorer folder,
   an email, etc.) and it attaches as a file. No need to hunt through folders.

Q: Nothing happens when I click - or the grid is empty.
A: An empty grid means <D2R>\logs\ has no files yet (the game writes them as
   it runs and crashes). Clicking copies silently - there's no popup, but the
   file is on your clipboard ready to paste.


--------------------------------------------------------------------------------
  MODS TOOL  (v1.6)
--------------------------------------------------------------------------------


Q: What does the Mods button do now?
A: It opens a grid of every folder in <D2R>\mods\ - including folders that
   don't have a modinfo.json yet. Folders with a modinfo show a normal folder
   icon and the mod's name; folders without one are greyed out with a red
   "No Mod Info" label so you can spot them.

Q: How do I view or edit a mod's info?
A: Click the mod's folder icon. For a mod that already has a modinfo.json,
   this opens the info in read-only view; click EDIT (top-right) to make the
   fields editable, then Save. For a folder with no modinfo, clicking it opens
   the editor directly so you can create one.

Q: What can I edit?
A: Every modinfo.json field: name, savepath, title, author, version,
   description, overview, docs, website, discord, banner, and the two update
   fields (GitHub / Manifest). "name" and "savepath" are required - the
   launcher won't save with either left blank.

Q: I created / edited a modinfo. Do I need to refresh?
A: No. The Mods grid and the main mod list both update the moment you save,
   so a newly-created mod appears right away.

Q: Is it safe? Will it break my modinfo.json?
A: The editor writes standard JSON with proper escaping, and only writes the
   fields that have values (plus the two required ones). If you're unsure,
   the file is plain text - back it up first and you can always inspect what
   the launcher wrote.
