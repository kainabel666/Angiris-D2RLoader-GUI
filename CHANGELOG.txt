V1.5.1
─────────────────────────────────────────────────────────────────────


NEW: Help and About readers use a themed reading font

  The README and FAQ readers now render in Georgia — a proper reading
  face — instead of the plain system font, so they look like part of the
  launcher while staying easy to read in long documents.

  For those who want full theming, user_layout.json has a new
  reader_use_app_font option (default false). Set it true to render the
  readers in your chosen display font instead; note that decorative faces
  like Exocet are harder to read in long passages, which is why it's off
  by default.


FIXED: Help and About windows now follow the UI-scale setting

  The reader text — and the rest of those windows — stayed a fixed size
  when you changed the UI scale, while the titles grew, so the two looked
  mismatched. The whole window now scales together with your UI-scale
  choice.


CHANGED: Discord icon in the Help window is easier to see

  On its own and at its smaller size, the Discord icon tended to blend
  into the stone background. It's now brightened so it stands out clearly.


FIXED: Esc no longer opens Discord in the Help window

  Pressing Esc to close the Help window could open the Discord link
  instead, because Esc was being read as a click on the Discord button.
  Esc now simply closes the window.


V1.5
─────────────────────────────────────────────────────────────────────


CHANGED: Modding panel redesigned around four sections

  The bottom panel — opened by the arrow under the center column — is no
  longer a single dense grid of a dozen buttons. It's now four clearly
  labelled sections in one row:

      REFERENCES   TOOLS   DOWNLOADS   TUTORIALS

  Clicking a section opens a small window listing that section's items.
  Short lists show as a single column; longer ones split into two. This
  keeps the panel itself compact — it no longer runs off the bottom of
  smaller screens the way the old tall grid did — while making room to
  add far more per section than the old layout could hold.

  REFERENCES and DOWNLOADS carry the same links as before; TOOLS launches
  the same local editors. TUTORIALS is new — a growing set of guide links
  (level creation, runewords, items and sets, and more).


NEW: Help opens an in-app FAQ reader

  The Help button used to open FAQ.txt in Notepad. It now opens a
  scrollable reader inside the launcher, styled to match the rest of the
  UI, with a "Need More Help?" prompt and a Discord link to the community
  server at the bottom.


FIXED: Esc in the About window triggered the download

  Pressing Esc to dismiss the About window could instead start the
  D2RLoader download, because the window's Esc handling collided with the
  Download button internally. Esc (and the About/Help/section windows
  generally) now closes cleanly. In the About window, if you're reading
  README or FAQ, Esc backs out to the main About view first.


FIXED: Launcher could start too large to use, with no way to recover

  On a 1080p display at 100% Windows scaling, the launcher offered UI
  scale options of 100% / 115% / 127% — but only 100% actually fits a
  1920x1080 screen. At 127% the window is 1958x1305, which is 273px
  taller than the usable desktop area.

  Because the Scale control sits near the bottom of the window, choosing
  one of those options put the control itself off-screen. The setting is
  saved, so restarting didn't help: the one control that could undo it
  was permanently out of reach.

  The scale options are now checked against your actual monitor, and any
  choice whose window wouldn't fit is stepped down to the largest one
  that does. This applies both when you change the setting and at
  startup — so anyone already stuck gets a usable window back on the
  next launch, without having to edit or delete any files.


CHANGED: UI scale options now account for screen size, not just DPI

  Previously the three offered scale options were chosen from your
  Windows DPI setting alone. That ignores resolution, and the two are
  not interchangeable: 1080p at 150% and 4K at 150% report the same DPI
  but have very different amounts of usable space.

  Your DPI setting still decides which options you're offered — it's
  your stated preference for how large things should be, and a 4K
  display always gets exactly what it asks for. Resolution now acts only
  as a limit, shifting the options down when the screen physically can't
  display them.

  Two smaller options (50% and 65%) were added for the cases that had
  nothing workable before — notably 1080p at 150%, where even the old
  smallest option of 75% overflowed the screen.

  What you'll be offered:

                  DPI 100%          DPI 125%          DPI 150%
      1080p       75/85/100         50/65/75          50/65/75
      1440p       100/115/127       75/85/100         65/75/85
      4K          100/115/127       85/100/115        75/85/100

  If you had previously set a scale that no longer appears in your list,
  it will be adjusted to the nearest option that fits.


FIXED: Long delay and visible "assembling" when opening the modding panel

  Clicking the expand arrow took roughly a second, and the panel visibly
  filled in piece by piece rather than appearing at once.

  The cause was in how the window background was drawn. Every repaint
  redrew the stone texture and frame artwork from scratch — around a
  dozen large image operations, each one resampled because the UI is
  drawn at a scale factor. Measured, a single full repaint cost roughly
  830ms.

  The static parts of the window (stone background, frame, panel borders,
  ornaments) are now composed once into an off-screen image at the exact
  size needed, and each repaint simply copies that image into place. The
  same work now costs about 1ms.

  This affects every full repaint, not just the modding panel — the
  launcher should feel more responsive when switching back to it from
  another window, restoring it from the taskbar, or changing settings.

  The first time you open (and the first time you close) the panel in a
  session still does the one-time composition for that state; every
  toggle after is immediate.


CHANGED: Larger window drag area

  The draggable strip along the top of the window extends 20px further
  down, making the window easier to grab. The title-bar buttons are
  unaffected.


CHANGED: Modding panel buttons resized

  The buttons in the References / Tools and Programs / Downloads sections
  are slightly smaller (252x52, from 280x58) with more space between
  them.

  They previously clipped one another. Each button reserves an invisible
  margin so its hover animation has room to draw, and that margin was
  sized for the much larger navigation buttons — about four times more
  than these needed. The surplus made neighbouring buttons overlap. The
  margin is now sized for these buttons specifically, and the row spacing
  matched to it.


CHANGED: Tool and reference names no longer vendor-branded

  "AFJ Pro Text Editor" is now "Text Editor", "Eez's Sprite Editor" is
  now "Sprite Editor", and "Eez's File Guides" is now "File Guides".
  The links and the programs they launch are unchanged.


FIXED: Minimize and close buttons could become invisible

  If btn_minimize.png or btn_close.png was missing or corrupt, the two
  title-bar buttons drew nothing at all — but stayed clickable, since
  the click detection is based on position rather than artwork. That
  left two invisible working buttons in the corner of the window.

  Both now fall back to a drawn control (a dash and a cross) that follows
  your chosen colour, so the window controls are always visible.


V1.4.1
─────────────────────────────────────────────────────────────────────


NEW: About modal (replaces the README-in-Notepad shortcut)

  The About button in the left rail used to shell-open README.txt in
  Notepad. It now opens a themed modal with two views:

    Hub view      Angiris version, the detected D2RLoader version,
                  a "Latest D2RLoader" download button, and a row of
                  square icon buttons for README, FAQ, and Discord.

    Reader view   README.txt and FAQ.txt render inside the modal in a
                  scrollable panel instead of launching an external
                  editor. Scroll with the mouse wheel. The Close button
                  returns you to the hub from a document, and closes
                  the modal from the hub (Esc does the same).

  The D2RLoader version is read from the file-version resource stamped
  into D2RLoader.exe. Builds without a version stamp, or a missing
  install, show "Not detected" rather than a blank or a guess.


NEW: One-click D2RLoader download + install

  The "Latest D2RLoader" button in the About modal downloads the
  current release from d2rloader.net and installs it into your D2R
  folder. The whole thing runs in the background with a status line
  in the modal:

    Downloading -> Verifying -> Extracting -> Installing -> Updating config

  Your D2RLoader.toml is never overwritten (see the config-merge entry
  below), and D2R/D2RLoader must be closed first (see the guard entry).


NEW: Download integrity check (SHA-256)

  d2rloader.net publishes a SHA-256 for each release. The launcher now
  fetches that hash and compares it against the bytes it actually
  downloaded before extracting anything.

  * Hash mismatch  -> the install ABORTS and nothing is written to your
                      game folder. A mismatch means a truncated
                      download, a stale CDN object, or tampering, and
                      unpacking that over a working install is exactly
                      what the checksum exists to prevent.
  * Hash not found -> the install continues, with a warning in the log.
                      The download already travels over HTTPS, so a
                      broken page scrape shouldn't disable updating.

  The full comparison is written to assets\d2rloader_install.log.


NEW: D2RLoader "Update Available" notice

  On startup the launcher checks d2rloader.net for the current release
  and compares it against your installed D2RLoader.exe. When a newer
  version exists, gold "D2RLoader Update Available" text appears above
  the LOADER OPTIONS header. Clicking it opens the About modal, where
  the download button does the update.

  The notice only appears when BOTH versions are known AND the site's
  is genuinely newer. Not installed, check failed, or already current
  all show nothing — it never claims an update it can't verify.
  Pre-release suffixes are ignored for the comparison, so 1.0.1 and
  1.0.1-beta are treated as the same version.

  Check details are logged to assets\d2rloader_check.log.


NEW: Running-game guard with "Close Now"

  Updating D2RLoader while D2R or D2RLoader is running would fail
  partway (their open handles lock the files). The launcher now checks
  before starting and offers to close the game for you:

    "D2R or D2RLoader is currently running and must be closed before
     updating. Close it now? (Any unsaved game progress will be lost.)"

  Choosing Yes terminates both processes, waits for the handles to
  release, verifies the field is clear, and continues straight into the
  download. Choosing No cancels.

  A second check runs immediately before any file is written, so
  launching the game DURING the download aborts cleanly rather than
  leaving a half-updated install.


NEW: Additive-only D2RLoader.toml merge

  When the launcher installs a D2RLoader update, your existing
  D2RLoader.toml is preserved and then AMENDED — never replaced:

  * Values you already have are never changed. If you set
    show_ground_sockets = true and the new release defaults it to
    false, you keep true.
  * Keys and sections that are new in the release get appended in a
    trailing block marked
        # ---- Added by Angiris Launcher (new D2RLoader keys) ----
  * Nothing is edited, reordered, or deleted.
  * The original is backed up to D2RLoader.toml.bak first.

  So a new loader feature gets its config keys without costing you any
  of your tuning.


NEW: Update-safe user files

  Updating the launcher no longer overwrites files that hold YOUR data:

      assets\user_layout.json
      assets\seeds.json
      assets\playtime.json

  These are preserved if they already exist, so custom layouts, seed
  history, and playtime totals survive an update. A first-time install
  still lays down the bundled defaults.

  Because user_layout.json is preserved, a migration step runs at
  startup that adds any NEW layout fields (with their defaults) to an
  existing file, leaving all your current settings and formatting
  untouched. That's how scale_as_dropdown reaches users who already
  have a layout file.


NEW: UI Scale as a dropdown (scale_as_dropdown)

  user_layout.json gains a "scale_as_dropdown" boolean. Set it true and
  the toolbar's Scale control becomes a click-to-open dropdown listing
  every preset available at your DPI, instead of a 3-state toggle you
  cycle through. One click to any scale.

      { "scale_as_dropdown": true }

  In dropdown mode the control is stacked like the On Launch column —
  "SCALE" header on top, value box below — and the box is wider than
  the toggle-mode one so three-digit values clear the chevron at
  heavier fonts. Default is false; the cycle toggle is unchanged.


CHANGED: Window pins to the top of the screen at maximum scale

  When you scale the UI to the highest preset for your DPI and the
  modding expand arrow is available, the window now pins its top edge
  to the top of the monitor's work area — but only if the fully
  expanded window would otherwise run off the bottom of the screen.

  This means you can open the expanded modding area at max scale
  without first dragging the window up. At any other scale, with the
  expand arrow hidden, or when the window already fits, the position is
  left exactly where you put it.


FIXED: Title-bar buttons vanished if their art was missing

  The minimize and close buttons drew nothing when btn_minimize.png or
  btn_close.png was missing or corrupt — but stayed clickable, since
  the hit test is geometry-based. That left invisible live buttons in
  the corner of the window.

  Both now fall back to a drawn control (dark plate, bronze border,
  gold glyph) that follows your chosen colour preset and keeps the
  press feedback. Corrupt files take the same path as missing ones.


V1.4
─────────────────────────────────────────────────────────────────────


NEW: D2RLoader beta 1.0 compatibility

  D2RLoader beta 1.0 replaced D2RLoader.ini with a TOML file
  (D2RLoader.toml) and reorganised every configuration key under
  new nested sections (e.g. [d2rcore.stash], [d2rloader.developer]).
  Angiris 1.4 reads and writes the new TOML format exclusively —
  it does NOT fall back to the old .ini.

  Users updating from v1.3 with an existing D2RLoader beta 1.0
  install: any settings the launcher exposes will be re-created in
  D2RLoader.toml the first time you change them. Settings the
  launcher does not surface are left untouched (the launcher only
  edits the specific keys it owns).


NEW: Plugin + patch discovery under d2rloader\

  D2RLoader beta 1.0 moved plugin discovery out of the mod's .mpq
  folder and into a sibling d2rloader\ folder. It also adds JSON
  memory patches alongside DLL plugins. New paths:

     <D2R>\d2rloader\plugins\      - global .dll plugins
     <D2R>\d2rloader\patches\      - global .json patches
     <D2R>\mods\<Mod>\d2rloader\plugins\   - mod-local plugins
     <D2R>\mods\<Mod>\d2rloader\patches\   - mod-local patches

  The Plugin Manager now shows plugins (.dll) and patches (.json)
  side-by-side under the same section headers, discriminated by
  filename extension. Enable/disable moves the file into a sibling
  Disabled\ folder the same way plugins were moved in v1.3, but
  now works for patches too. Friendly names via plugin_manifest.json
  apply uniformly to both.

  plugin_config.json (per-mod plugin/patch curation) stays at the
  mod root; its "plugins" array may now list both .dll and .json
  filenames mixed together — the launcher routes each to the
  correct destination folder by extension.


NEW: Basic Options and Developer Options modals

  Loader Options section is now a three-button stack:

     LOADER OPTIONS  [ ... ]
     Basic Options            - opens themed popup with 6 settings
     Developer Options        - opens themed popup with 10 settings
     Plugins                  - opens the Plugin Manager (unchanged)

  Basic Options exposes:
     Show Sockets                 [d2rcore.items] show_ground_sockets
     Show Item Level              [d2rcore.items] display_item_levels
     Respec Skill/Stats           [d2rcore.player] enable_respec
     Stash Tabs (0-16 dropdown)   [d2rcore.stash] add_shared_tabs
     Material Limit (0-255 text)  [d2rcore.stash] set_materials_limit
     Show TCP/IP Button           [d2rloader] show_tcpip_button

  Developer Options exposes:
     Enable Console               [d2rloader.developer] enable_console
     Assert Dialog Message        [d2rloader.developer] assert_dialog_mode
     Enable Logging               [d2rloader.developer.logs] enabled  (master)
       JSON Resources             [...] json_resources
       Widget Panel Creation      [...] widget_panels
       Excel File Loaded          [...] excel_files
       True and Open Type Fonts   [...] fonts
       UI Sprites Creation        [...] sprites
       Chat Messages              [...] chat_messages
       Models Creation            [...] models

  The 7 log-detail toggles under Enable Logging are greyed out and
  inert when the master toggle is off. All settings apply immediately
  on click; no Save/Cancel dance because D2RLoader only reads the
  toml at launch anyway.

  Material Limit is a text box (not a dropdown) since the 0-255
  range is too wide for a menu. A "Default = 99, Max = 255" note
  below the label documents the range; out-of-range values snap
  to the nearest bound on focus-loss.


CHANGED: Loader Options main-panel restack

  Stash Tabs and Show Sockets are no longer separate rows on the
  main screen — they moved into Basic Options. In their place, the
  Loader Options section now hosts three same-height buttons
  (Basic Options, Developer Options, Plugins) with the "..." folder
  picker still at the top-right of the section header.


CHANGED: Options left-rail nav button removed

  The "Options" nav button (which shell-opened D2RLoader.toml)
  was removed. Settings live in Basic/Developer Options now; the
  toml is still hand-editable if you want to touch keys the
  launcher doesn't expose.

  The left rail now has 5 nav buttons instead of 6, freeing
  vertical space above the Loader Options section.


CHANGED: launcher-enforced defaults on startup

  Every launcher start (and every D2R path change) writes:
     [d2rloader] default_mod       = ""
     [d2rloader] skip_title_screen = false
  These are the two toml keys that would bypass Angiris's mod
  picker — with default_mod set, D2RLoader would launch straight
  into that mod, skipping the launcher entirely. Angiris resets
  them each run so the launcher stays the entry point.


FIXED: Loader Options frame extending past the section bottom

  Frame-height calculation was reading a stale HWND rect on some
  DPI configurations, causing the bg_loader_options frame to
  stretch far below the Plugins button. Now derived directly from
  the section's known geometry.


FIXED: LOADER OPTIONS header clipping with wider font families

  At 150% Windows DPI + heavier fonts (Exocet Med), "LOADER OPTIONS"
  rendered wider than the header rect and the tail letters were
  clipped by GDI+. The header now measures the text with the
  primary font and falls through to smaller fonts if it wouldn't
  fit, so the label is always rendered whole.


FIXED: Full-window repaint on every focus change

  The main window's WM_ACTIVATE handler was calling RedrawWindow
  with RDW_INVALIDATE | RDW_ALLCHILDREN on every activation —
  including modal closes, alt-tab back, etc. That caused the whole
  launcher (assets, buttons, background) to repaint each time.
  Now the heavy full-redraw only fires when restoring from a
  minimized state (where the owner-draw buttons would otherwise
  show default light-gray for a frame); routine activations use
  the normal partial-invalidation Windows provides.


V1.3
─────────────────────────────────────────────────────────────────────


NEW: Per-mod plugin configuration (plugin_config.json)

  Mod authors can ship a plugin_config.json file inside their mod's
  root folder listing exactly which plugin DLLs the mod expects to
  use with D2RLoader. When a user selects such a mod:

  * The Plugin Manager window shows the configured plugin list in a
    read-only "inventory" view — no toggling — with any missing
    plugins greyed out.
  * All global plugins are moved to the global Disabled folder while
    that mod is active, so D2RLoader won't load anything outside the
    author's curated list.
  * If a plugin is listed but not in the mod's plugins folder, the
    launcher auto-recovers it from the global folders or from the
    mod-local Disabled folder if possible. Globals are copied (so
    other mods keep working); mod-local disabled entries are moved.
  * The same globals-to-disabled sweep runs when you press PLAY,
    closing the loophole where switching between mods could have
    left globals enabled at launch time.

  If plugin_config.json lists no plugins (an empty array), the
  Plugin Manager instead shows a centred message:
        "<Author> has selected to disable plugins for <Mod Name>"
  Author + mod name come from modinfo.json; a generic fallback is
  used if either field is missing.


NEW: Launcher-wide plugin renaming (plugin_manifest.json)

  A plugin_manifest.json file beside the launcher stores friendly
  display names for plugin DLL filenames. Every plugin row shows
  its display name with the DLL filename in parentheses:
        "D2 LoD Helper (d2lod.dll)"

  * Right-click any plugin row in the Plugin Manager and pick
    Rename... to enter a new display name. Updates are saved
    immediately and take effect for every mod that uses that DLL.
  * The manifest is safely hand-editable — the format is a flat
    JSON map of "dll_name.dll": "Friendly Name" pairs. Case-
    insensitive matching means you don't have to worry about
    capitalisation, and the launcher auto-populates the manifest
    with empty entries for every plugin DLL it encounters, so you
    can just open the file in a text editor and fill in names
    beside the pre-populated keys.
  * A curated default plugin_manifest.json ships with the launcher.


NEW: Show Sockets toggle in Loader Options

  A two-state toggle in the Loader Options section that writes
  "true" or "false" to [Items] show_ground_sockets in D2RLoader.ini.
  When on, D2RLoader shows the number of sockets on items on the
  ground.


CHANGED: Loader Options layout

  The Loader Directory text bar was removed to make room for new
  rows. The "..." button (which picks your D2R install folder) is
  still there — it moved up next to the LOADER OPTIONS header. Same
  behaviour, just tighter vertical footprint.

  New stack (top to bottom):
      LOADER OPTIONS  [ ... ]
      Stash Tabs                  [ N ▾ ]
      Show Sockets                [ toggle ]
      Plugins button (opens the Plugin Manager)


CHANGED: Plugin Manager visual reskin

  * Stone-textured background and ornate bronze/gold frame matching
    the main window's mod list panels.
  * Buttons use the same nexus-update-style artwork as the main
    window's Plugins button, with hover glow and click shrink.
  * Checkboxes now use the same asset family as the Launch Options
    section.
  * Section headers ("Global plugins" / "Mod plugins") replace the
    "(G)" / "(M)" tags that used to appear inline on each row. The
    Global section is hidden entirely in per-mod-config mode.
  * The Save/Cancel or Close buttons at the bottom sit further from
    the list and are a touch taller, so they read as a distinct
    button row instead of feeling crammed against the last plugin.


CHANGED: Rename modal visual style

  Same stone-textured background, ornate frame, and nexus-update
  buttons as the Plugin Manager. The input field itself is a black
  well framed by the launcher's text_box artwork.


CHANGED: Plugin Manager click behaviour

  Clicking anywhere in a plugin row no longer selects it — only
  clicking directly on the checkbox toggles the plugin. The
  selection highlight that used to follow the mouse around is gone
  entirely, so there's no more distracting flicker as you scan the
  list.


FIXED: Button hover glow was inconsistent

  Buttons that don't grow on hover (Plugins, Refresh, and the
  new Save/Cancel/OK buttons in the Plugin Manager and Rename
  modal) now show their gold text glow on hover consistently.


V1.2
─────────────────────────────────────────────────────────────────


NEW: Per-mod playtime tracking

  • The launcher records cumulative play time for each mod and the
    date it was last played.
  • Hover over any mod row for two seconds to see a tooltip with the
    mod's total playtime and last-played date.
  • Tracking starts when D2R is detected as running after launching a
    mod, and stops when D2R exits. Time spent in the launcher itself
    isn't counted.
  • Data stored in assets\playtime.json, keyed by mod folder so it
    survives reinstalls.


NEW: Right-click context menu on mod rows

  Right-click any mod for a themed menu with:
    Backup Saves   - manually snapshot the mod's save folder.
    Re-zip         - package the mod folder back into a .zip in
                     <D2R>\mods\ (useful for sharing or backing up).
    Uninstall      - delete the mod from <D2R>\mods\ entirely (asks
                     for confirmation; a save backup runs first).


NEW: Save backup system

  • The mod's full save folder (under
    %USERPROFILE%\Saved Games\Diablo II Resurrected\Mods\<savepath>\)
    gets snapshotted into a "backups\<YYYY-MM-DD_HHMMSS>\" subfolder
    next to the save data it protects.
  • Manual snapshot via the right-click "Backup Saves" menu item.
  • Automatic snapshot before any Overwrite install (where the
    destination mod folder is about to be wiped) and before any
    Uninstall.
  • Rotation keeps the five most recent snapshots; older ones are
    pruned automatically.


NEW: Launcher self-update

  • The launcher checks GitHub for newer releases on startup.
  • When a newer version is available, the version label in the left
    rail (under the logo) glows gold and becomes clickable.
  • Clicking it opens the update prompt with three options:
        Update            - download and install in place
        Skip This Version - dismiss for this specific version
                            (remembered until a newer version ships)
        Ignore            - dismiss just this once (prompt reappears
                            on next launch)
  • Clicking Update hides the main window, releases its locked
    assets, and shows a minimal install popup with three statuses:
        Downloading -> Updating -> Complete
  • A Restart button appears at Complete (enables half a second
    later to prevent accidental clicks). Clicking it spawns the new
    launcher and closes the running one.


NEW: Self-update old-version cleanup

  • The previous launcher exe is renamed to Angiris.exe.old during
    the update.
  • Every startup checks the install folder for an .old file and
    deletes it if present.
  • Fast attempt up front handles orphaned .old files immediately.
  • If the prior launcher process is still releasing its image file,
    a 2-second background timer keeps retrying for up to 30 seconds.
  • Final fallback schedules the delete for the next Windows reboot
    via MoveFileEx, so the user never has to clean up manually.


CHANGED: Version label position

  Moved 30 px below the logo to make room for the click-target and
  glow effect when a launcher update is available.


CHANGED: Font files skipped during launcher self-update

  Windows holds an internal mapping for any font that's been used
  to rasterize glyphs in the current process, which makes the
  active font's .ttf impossible to overwrite during a live update.
  Fonts essentially never change between launcher releases, so they
  are now skipped at the extraction stage of the self-update flow
  and don't even land in the temp directory. Users who want a font
  swap can drop new .ttf files into assets\fonts\ manually.


FIXED: Self-update install logging readability

  Diagnostic logs (last_update_check.log, last_update_install.log)
  no longer truncate paths and status text to a single character.
  Caused by a printf wide-string format mismatch in the MinGW build
  — every wide-string log line now prints full content correctly.


V1.1
─────────────────────────────────────────────────────────────────


NEW: Drag-and-drop mod installer

  • Drop one or more .zip files onto the launcher to install them
    into <D2R>\mods\.
  • Multiple drops queue and process sequentially.


NEW: Folder collision dialog

  Shown when a mod's target folder already exists.
    Update     — overwrite same-named files, add new files,
                 preserve folder-only files.
    Overwrite  — wipe destination, extract fresh.
    Cancel     — skip this archive.


NEW: D2R path missing dialog

  Shown when a zip is dropped before the D2R install folder is set.
    Set Path   — opens the folder picker.
    Cancel     — clears the install queue.


NEW: Invalid mod archive dialog

  Shown when a dropped zip contains no modinfo.json. Names the
